# Plan 01-02: Security Rules Hardening

## Objective
Update the `firestore.rules` to reflect the new server-side bidding architecture. Ensure clients cannot write to the `auctions` collections while opening the `bids` subcollection for public reading, enabling competitive transparency.

## Tasks

```xml
<task>
<description>Update Firestore rules for Auctions</description>
<read_first>
- firestore.rules
</read_first>
<action>
1. Locate the `match /auctions/{auctionId}` rule in `firestore.rules`.
2. Keep the `allow read: if true;` rule.
3. Change `allow write: if isAdmin(request);` to explicitly list operations. 
   - `allow create, delete: if isAdmin(request);`
   - `allow update: if isAdmin(request);`
4. The client should no longer have ANY write access to `auctions`, since API updates bypass these rules.
</action>
<acceptance_criteria>
- `firestore.rules` blocks non-admin updates to the `auctions` collection.
- `allow update` requires `isAdmin(request)` for auctions.
</acceptance_criteria>
</task>

<task>
<description>Update Firestore rules for Bids</description>
<read_first>
- firestore.rules
</read_first>
<action>
1. Locate the `match /auctions/{auctionId}/bids/{bidId}` rule.
2. The current rule restricts reading: `allow read: if isAdmin(request) || resource.data.userId == request.auth.uid;`.
3. Change the read rule to public so users can see the bid history of the auction they are viewing:
   - `allow read: if true;` (or `if isLoggedIn(request);` to prevent anonymous stalking, but public is usually preferred for auctions).
4. Update write access:
   - `allow create: if isAdmin(request);` (Regular user writes now go through the API).
   - `allow update, delete: if isAdmin(request);`
</action>
<acceptance_criteria>
- `firestore.rules` allows `read` on the `bids` subcollection for all users.
- `firestore.rules` blocks non-admin updates/creates on `bids`.
</acceptance_criteria>
</task>
```

## Verification

**must_haves:**
1. A regular user cannot update an auction document directly via client.
2. A regular user CAN see the complete bid history (all bids) for an auction on the frontend.
3. Only the `firebase-admin` API (or admins) can create new bids.
