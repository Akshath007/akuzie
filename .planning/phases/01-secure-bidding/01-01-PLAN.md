# Plan 01-01: Migrate Bidding to Secure API

## Objective
Move the `placeBid` logic from the client to a secure Next.js API route (`firebase-admin`). This allows regular users to bid without being blocked by client-side Firestore security rules.

## Tasks

```xml
<task>
<description>Create the secure bidding API route</description>
<read_first>
- src/lib/auction-data.js
- src/lib/firebase-admin.js
</read_first>
<action>
1. Create `src/app/api/auction/bid/route.js`.
2. Implement a POST handler that accepts `auctionId`, `bidAmount`, `userId`, `userName`, and `userEmail`.
3. Verify the user's identity by checking the `Authorization` header for a valid Firebase ID token (using `firebase-admin` auth).
4. Run a Firestore transaction using `firebase-admin` (similar to the existing one in `auction-data.js`):
   - Check if the auction exists and is active.
   - Verify the new `bidAmount` is strictly greater than the current `currentBid`.
   - Update `currentBid` and `currentBidder`.
   - Apply anti-sniping logic (extend time by 3 minutes if within the last 3 minutes).
   - Add a new document to the `bids` subcollection.
5. Return a success JSON response.
</action>
<acceptance_criteria>
- `src/app/api/auction/bid/route.js` exists and exports a `POST` function.
- The route uses `admin.firestore().runTransaction`.
- The route verifies Firebase ID tokens.
</acceptance_criteria>
</task>

<task>
<description>Update the client-side placeBid function</description>
<read_first>
- src/lib/auction-data.js
- src/context/AuthContext.js
</read_first>
<action>
1. Modify the `placeBid` function in `src/lib/auction-data.js`.
2. Remove the direct Firestore transaction logic from this function.
3. Update it to perform a `fetch('/api/auction/bid', { method: 'POST', ... })`.
4. Ensure the current user's Firebase ID token is retrieved (using `auth.currentUser.getIdToken()`) and passed in the `Authorization: Bearer <token>` header.
5. Handle API errors gracefully and `throw Error(message)` so the UI can catch and display them.
</action>
<acceptance_criteria>
- `src/lib/auction-data.js` `placeBid` function uses `fetch`.
- `getIdToken()` is called to authenticate the API request.
- No direct client-side Firestore `runTransaction` remains for bidding.
</acceptance_criteria>
</task>
```

## Verification

**must_haves:**
1. Users can place a bid through the API successfully.
2. The API rejects requests without a valid Firebase ID token.
3. Race conditions are prevented via Server-side Firestore transactions.
